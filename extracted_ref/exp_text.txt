9. Interpretation of the results 
The testing shows that SHIFT is working as a complete prototype and not only as a UI mock-up. The 
application can collect keyboard events, apply privacy checks, group typing into sessions, store the required 
statistics in SQLite and show kinematic results through the GUI. The current kinematic screen also shows that 
the system can calculate transition time, physical distance and a velocity proxy from the collected events. 
The personal baseline in the latest analysis is 363 ms, while the average latency is 279 ms. The screen 
reports 24 high-latency patterns, meaning those transitions are above the personal threshold used by the 
analysis. The K-Means summary divides the analysed transition data into two groups with different average 
timing and distance. 
The privacy screen confirms that processing is local, there are no cloud API or network uploads, and raw 
typed content is not stored. The application also provides fail-closed protection and configurable exclusions. 
These features are important because the project deals with keyboard behaviour while the user is doing 
normal work. 
10. Final conclusion 
Based on the automated and manual tests, the main functions of SHIFT were successfully validated. The final 
regression suite passed 258 tests with no failures. The latest UI run also produced working dashboard, 
session, insight, kinematic, K-Means, heatmap, privacy and settings views. The final persistence check 
confirmed that the application can retain its aggregate session data locally. 
The screenshots in this report are the latest evidence supplied for the completed prototype. The automated 
test screenshot is included separately because it gives the clearest proof of the regression-test result.
